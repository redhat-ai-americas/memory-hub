# MemoryHub Extended Team Demo — 2026-08-14

Three segments, ~20 minutes total. Everything runs from the mcp-rhoai
cluster. The only local requirement is a browser and a terminal with
Claude Code.

---

## Segment 1: SOC Operational Display (~8 min)

**What it shows:** Four AI agents on four different frameworks (Claude
Code, FIPS-Agent, Hermes, OpenClaw) investigating a cybersecurity incident
together through shared MemoryHub memory. Nothing is pre-canned; the
scenario data represents real LLM calls and real MCP tool operations.

**URL:** https://soc-frontend-soc-demo.apps.cluster-n7pd5.n7pd5.sandbox5167.opentlc.com

**How to run:**

1. Open the URL in a browser. You'll see the standby screen with four
   agent cards and a REPLAY button.
2. Click REPLAY. All 37 events load instantly in burst mode.
3. Step through with SPACE or arrow keys at your own pace.

**Key beats to narrate:**

| Phase | What happens | What to point out |
|-------|-------------|-------------------|
| 1 - Detection | Tier 1 gets a SIEM alert, searches shared memory, finds a prior incident pattern match | Cross-incident pattern recall across time |
| 2 - Forensics | Forensics builds a timeline, references the same prior incident memory | Different agent, different framework, same memory |
| 3 - Attribution | Threat Intel writes an attribution assessment | Third framework writing to the same project |
| 4 - Contradiction | Forensics and Intel disagree on dwell time. MemoryHub preserves both versions | Contradiction handling: both memories kept, IC synthesizes |
| 5 - Containment | IC reads all findings, coordinates. Forensics triggers PII quarantine | Curation guard blocks a write containing sensitive data |
| 6 - Shift Change | driver_id changes from Jason Park to Maya Chen | Governance: actor_id (the agent) stays the same, driver_id (the human on shift) changes. Audit trail survives the handoff |
| 7 - Audit | Full audit trail query across all agents and both shifts | Every operation attributed to both agent role and human operator |

**If someone asks about the models:** The Tier 1 agent uses Claude (cloud
API). The other three use GPT-OSS 20B hosted on-cluster via vLLM. The
display shows this on each agent card.

## Segment 2: Admin UI Walkthrough (~5 min)

**What it shows:** The governance and observability layer. How an admin or
platform team sees what's in MemoryHub.

**URL:** https://memoryhub-ui-memoryhub-ui.apps.cluster-n7pd5.n7pd5.sandbox5167.opentlc.com/

**How to run:**

1. Open the URL. It authenticates via OpenShift OAuth (you'll be logged
   in as kube:admin).
2. Walk through the views.

**What to show:**

- **Stats overview** -- 7,262 memories across 5 scope levels (user,
  project, organizational, enterprise, entity). MCP health indicator.
- **Graph view** -- 7,262 nodes, 882 edges. Visual representation of
  the memory graph with version chains and relationships.
- **Project filter** -- Filter to `midwest-financial-soc` (91 memories)
  to show the SOC scenario data you just walked through in Segment 1.
  This connects the operational display to the governance view.
- **Memory detail** -- Click a node to show content, scope, weight,
  version history, branch structure. Point out the `source: dreaming`
  tag on memories that were extracted from conversations (not written
  directly by an agent).
- **Recent activity** -- The IR-2024-184 incident data is visible in the
  activity feed.

**Talking points:**

- Multi-tenant by design. Every memory has a tenant_id. Different teams
  see different data.
- The graph isn't just flat key-value storage. Memories form trees with
  branches (rationale, provenance, contradiction). Version history is
  preserved, not overwritten.
- Everything here is queryable through the MCP API. The UI is a viewer,
  not the primary interface. Agents are the primary consumers.

## Segment 3: Claude Code Live Interaction (~5 min)

**What it shows:** The developer experience. An AI coding assistant that
accumulates institutional knowledge across conversations through
MemoryHub.

**How to run:**

1. Open a terminal with Claude Code. It connects to the mcp-rhoai
   MemoryHub instance automatically via the session hooks.
2. Do live memory operations in conversation.

**Script (adjust to feel natural):**

1. **Search for SOC context:**

   > "Search MemoryHub for credential compromise response patterns"

   This should return memories from the SOC scenario. Point out that
   Claude Code found context written by completely different agents on
   different frameworks.

2. **Write a new memory:**

   > "Remember in MemoryHub that we switched the dreaming extraction
   > pipeline to use on-cluster GPT-OSS 20B instead of the Gemini API,
   > to keep data on-cluster and eliminate external dependencies."

   Show the write succeeding with weight, scope, and curation feedback
   (similar memory detection).

3. **Search for what you just wrote:**

   > "Search MemoryHub for our dreaming pipeline configuration"

   The memory you just wrote should come back. Point out that this would
   persist across sessions and be available to any agent with access to
   the same MemoryHub instance.

**Talking points:**

- MemoryHub integrates via MCP (Model Context Protocol). Any tool that
  speaks MCP can connect. Claude Code, LangChain, custom agents, the
  CLI, the SDK.
- The dreaming pipeline extracts facts from conversations automatically.
  You don't have to explicitly write every memory. MemoryHub watches
  conversation threads and distills durable knowledge in the background,
  using an on-cluster LLM (GPT-OSS 20B).
- This is running on OpenShift with Red Hat UBI base images and FIPS
  compliance. The embedding model (Granite) and the extraction model
  (GPT-OSS 20B) both run on-cluster. No data leaves the environment.

## Cluster service inventory (for Q&A)

|---------|-----------|------------|

| Reranker | reranker-model | Granite Reranker (on-cluster) |
| Object storage | memory-hub-mcp | MinIO |
| Session cache | memory-hub-mcp | Valkey |
| SOC demo frontend | soc-demo | FastAPI + vanilla JS |

## Fallback plan

If the cluster is unreachable tomorrow morning:

- **SOC demo:** Run locally with `cd demos/soc-demo/front-end/soc-frontend
  && uvicorn server:app --port 8000`, then `python3 replay.py --pace 0`
  in another terminal. Open `http://localhost:8000`.
- **Admin UI:** Show screenshots or skip this segment.
- **Claude Code:** The local MemoryHub instance
  (memoryhub-local) can serve as a backup for live memory operations,
  though it won't have the SOC data.
